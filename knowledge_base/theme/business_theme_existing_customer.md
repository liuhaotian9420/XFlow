# 主题三：老客经营、复贷分析与商业化收入

## 主题定义

这一组 SQL 服务于老客经营复盘。核心问题不是“今天有没有放款”，而是“老客复贷质量如何、经营动作是否有效、商业化产品贡献了多少收入”。

## 典型文件

- `老客月会sql代码.ipynb`
- `xyf_jingying.weekly_analysis_report_df_lss.txt`
- `xyf_jingying.weekly_analysis_report_vip_dynamic_income_lss.txt`

## 典型分析对象

- APP 复贷 / 加贷
- API 拉回 APP
- APP 内复贷
- 会员卡
- 飞跃卡
- 提额卡
- 额外放开人群
- 人群池

## 高频问题

- 放款量级和结构变化
- vintage / MOB 风险表现
- 24 / 36 等价格带或资产类别表现
- 会员产品收入、退款、净收入
- 额外放开是否带来增量
- 客群池是否还有经营价值

## 隐含的业务背景

- 这类 SQL 面向经营会议或专题汇报，通常希望一份材料覆盖多个维度。
- 不同 SQL 之间共享同一批经营标签，例如复贷分组、风险等级、会员卡类型、客群池活跃度。
- 商业化收入分析和贷款经营分析被放在一起，说明业务上会把“贷款收益”和“增值收入”一起看。

## 可能对应的业务需求

- “做一份老客复贷月会分析 SQL，覆盖放款、风险、价格、在贷、人群池。”
- “按月看会员卡/飞跃卡/提额卡的收入、退款、净收入。”
- “评估额外放开策略对放款量和质量的影响。”
- “比较 API 拉回 APP 与 APP 内自然复贷的差异。”
- “按模型分或风险分层看老客申请通过率、资金通过率、放款金额。”

## 生成 SQL 时应优先具备的能力

- 支持多段 SQL 素材组合成专题分析。
- 支持月维度、周维度、累计窗口输出。
- 支持 vintage 和账龄指标。
- 支持收入、退款、净收入三类口径。
- 支持把经营标签和风险标签叠加到同一分析宽表。
