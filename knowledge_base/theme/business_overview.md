# SQL 业务背景总览

这组 `sql代码` 不是一套统一的数仓开发脚本，更像是经营分析、监控报表、专项复盘和策略验证的 SQL 素材库。

整体上可以分成 3 个业务主题：

## 1. 放款与审批监控

代表文件：
- `ads_inloan_loan_monitor_screen_df.sql`
- `ads_inloan_loan_pass_monitor_df.sql`
- `dws_inloan_loan_channel_stat_df.sql`
- `dws_inloan_loan_pass_stat_df.sql`
- `dws_inloan_loan_risk_stat_df.sql`
- `ads_inloan_loan_balance_mthly_df.sql`

业务背景：
- 面向日常经营看板、邮件日报、月内进度追踪。
- 关注放款金额、放款单量、风险通过、资金通过、在贷余额、月度累计、目标达成。
- 常见拆分维度包括新客/老客、APP/API、首贷/复贷/加贷、资产类别、是否近期被拒。

可能对应的业务需求：
- 生成某日或某月的放款监控日报 SQL。
- 生成按渠道、客群、风险口径拆分的放款/通过率 SQL。
- 生成月累计进度 vs 目标值的完成度看板 SQL。
- 生成余额、在贷、逾期区间分层 SQL。

## 2. 新客转化与授信经营

代表文件：
- `APP新客转化-授信口径.ipynb`
- `APP新客转化-注册口径.ipynb`
- `授信口径转化率_虚假给额.ipynb`

业务背景：
- 面向新客增长链路，关注注册、授信、提现、放款、渠道归因、虚假给额、额外放开。
- SQL 会把用户放到不同转化口径下，例如注册口径、授信口径、放款口径。
- 同时会引入风控评级、授信额度、是否 API 授信、渠道归因、用户年龄、分组实验等标签。

可能对应的业务需求：
- 生成新客注册到授信、授信到提现、提现到放款的漏斗 SQL。
- 生成渠道维度转化率 SQL。
- 生成虚假给额识别与影响评估 SQL。
- 生成授信额度带、风控等级、年龄段等分层转化 SQL。

## 3. 老客经营、复贷分析与会员收入

代表文件：
- `老客月会sql代码.ipynb`
- `xyf_jingying.weekly_analysis_report_df_lss.txt`
- `xyf_jingying.weekly_analysis_report_vip_dynamic_income_lss.txt`

业务背景：
- 面向老客复贷经营、月会复盘、会员卡/提额卡商业化收入、客群池运营。
- 既看放款规模，也看 vintage、风险质量、价格结构、会员收入、额外放开、人群池转化。
- 这类 SQL 常带有“汇报材料”属性，口径多、标签多、专题性强。

可能对应的业务需求：
- 生成老客复贷月报 SQL。
- 生成 vintage/MOB 风险表现 SQL。
- 生成会员卡、飞跃卡、提额卡收入动态 SQL。
- 生成人群池规模、活跃度、经营可投放性、30 天内转化 SQL。

## 4. 对 sql-generator 技能的启发

如果后续要让 `sql-generator` 根据业务需求自动出 SQL，这批参考文件最适合沉淀为以下能力：

- 监控型 SQL 模板
  - 输入日期、口径、渠道、客群，输出日报/月报。
- 漏斗型 SQL 模板
  - 输入起点口径、终点事件、分层维度，输出转化漏斗。
- 经营复盘型 SQL 模板
  - 输入主题和统计周期，输出按月/按周专题分析 SQL。
- 商业化收入型 SQL 模板
  - 输入产品类型、交易口径、累计窗口，输出收入/退款/净收入 SQL。

## 5. 使用建议

若用户后续提需求，可以先判断落在哪个主题，再从对应文档挑口径：

- “日报、看板、监控、完成度、通过率” 优先归到放款与审批监控。
- “注册、授信、新客、渠道、虚假给额” 优先归到新客转化与授信经营。
- “老客、复贷、月会、会员卡、提额卡、人群池” 优先归到老客经营与商业化分析。
