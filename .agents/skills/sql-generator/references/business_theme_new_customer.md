# 主题二：新客转化与授信经营

## 主题定义

这一组 SQL 围绕新客从进入产品到最终放款的经营链路，核心不是单纯统计放款，而是解释转化过程发生了什么，以及哪些人群、渠道、授信策略带来了差异。

## 典型文件

- `APP新客转化-授信口径.ipynb`
- `APP新客转化-注册口径.ipynb`
- `授信口径转化率_虚假给额.ipynb`

## 典型链路

- 注册
- 授信成功
- 提现发起
- 风险通过
- 资金通过
- 放款成功

## 高频标签

- 渠道归因
- 授信类型
  - APP
  - API
  - 小程序
- 授信额度带
- 风控等级
- 年龄段
- 是否虚假给额
- 是否额外放开
- 实验分组/随机分组

## 隐含的业务背景

- 新客经营不只是“多拉新”，而是要平衡转化率、风险、授信策略、渠道质量。
- SQL 里出现大量标签拼接，说明业务方经常要做分层复盘和专项专题分析。
- “虚假给额”被单独拿出来，说明存在授信表象与真实可贷能力之间的经营问题。

## 可能对应的业务需求

- “按注册口径看新客 30 天内授信、提现、放款转化率。”
- “按授信口径看不同渠道、不同额度带的放款表现。”
- “分析虚假给额人群的规模、转化率和放款金额。”
- “分析 APP 授信与 API 授信在放款结果上的差异。”
- “按风控等级、年龄、渠道看新客转化漏斗。”

## 生成 SQL 时应优先具备的能力

- 支持漏斗分阶段聚合。
- 支持同一用户跨阶段去重。
- 支持渠道/授信/风控/额度等多维分层。
- 支持 7 天、30 天等窗口转化。
- 支持把专项标签插入主表，例如虚假给额、额外放开、实验组。
