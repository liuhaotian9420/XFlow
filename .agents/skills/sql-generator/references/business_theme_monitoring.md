# 主题一：放款与审批监控

## 主题定义

这一组 SQL 服务于经营监控，而不是深度归因研究。核心目标是把贷款业务当前发生了什么、是否达成目标、风险/资金通过是否异常，用较稳定的指标体系表达出来。

## 典型文件

- `ads_inloan_loan_monitor_screen_df.sql`
- `ads_inloan_loan_pass_monitor_df.sql`
- `dws_inloan_loan_channel_stat_df.sql`
- `dws_inloan_loan_pass_stat_df.sql`
- `dws_inloan_loan_risk_stat_df.sql`
- `ads_inloan_loan_balance_mthly_df.sql`

## 典型指标

- 放款金额
- 放款单量
- 月累计放款
- 目标值/完成度
- 风险通过人数/通过率
- 资金通过率
- 在贷余额
- 30/90/180 余额口径
- 最近 30 天拒绝标识

## 常见业务拆分

- APP / API
- 首贷 / 复贷 / 加贷
- 新客 / 老客
- 资产类型
- 风险等级
- 日期口径
  - 日
  - 周
  - 月累计

## 隐含的业务背景

- 业务方已经有比较稳定的日报和月内经营节奏。
- 数据产出不仅用于分析，也用于管理层看板或邮件任务。
- 很多 SQL 自带 `MAX_PT`、月内过滤、当月累计逻辑，说明这类需求对“实时可更新”要求高。

## 可能对应的业务需求

- “帮我生成一个某月放款监控日报 SQL，按 APP/API 和首复贷拆分。”
- “帮我统计某客群最近 30 天风险通过率和资金通过率。”
- “帮我看本月每天放款金额、累计金额、目标完成率。”
- “帮我看余额口径在 30/90/180 天内的变化情况。”
- “帮我输出一份可邮件推送的监控表结果 SQL。”

## 生成 SQL 时应优先具备的能力

- 自动带日期窗口和 `MAX_PT`。
- 支持固定业务口径枚举。
- 支持 `UNION ALL` 拼出多组经营口径。
- 支持目标表或目标值表 join。
- 支持监控指标稳定排序和命名。
